概念說明

Agent / Skill 白話說明

給非資訊背景學員看的簡明說明：先理解三種程度，再回到自己的工作判斷適合做到哪一步。

這頁只做一件事：讓學員分清楚一次性需求、Skill 與 Agent。課堂不要求現場建立正式工具。

先用一個例子理解

第一次做

你先跟 Codex 說明情境：我有一份逐字稿，要整理成文章草稿，請先列重點與需要確認的事。

做過幾次後

你發現每次都會要求讀者、用途、摘要、待確認事實與人工審閱，這些穩定規則就可以整理成方法。

Skill 是什麼

Skill 可以先把它想成「工作方法小抄」。當同一類事情做過幾次後，你會知道每次都要交代哪些資料、要產出什麼格式、哪些地方一定要人看。把這些固定下來，下次就不用重新解釋一大段。

  • 適合重複但不太複雜的工作。
  • 重點是固定語氣、格式、檢查項目與不能做的事。
  • 它不代表會自動送出、寫回系統或取代人判斷。

Agent 是什麼

Agent 可以先把它想成「有任務邊界的工作助理」。它不只是改一句話，而是依照你給的目的，連續做幾個步驟：先看資料、整理狀態、列出問題、產出草稿，再提醒你哪些地方要確認。

  • 適合有多個步驟、會遇到例外的工作。
  • 需要說清楚資料來源、完成標準、停止點與確認責任。
  • 正式自動化前，要另外確認權限、風險與責任分工。

兩者差在哪裡

問題SkillAgent
適合什麼格式固定、規則清楚、每次都很像的工作。步驟比較多、要看狀態、需要中途停下確認的工作。
要先準備什麼常用格式、輸出樣子、檢查清單。工作目標、資料來源、流程、停止規則、確認責任。
今天課堂做到哪裡先知道哪些做法值得整理成方法。先知道哪些工作未來可能適合設計成助理流程。

怎麼判斷要不要升級

  1. 這件事是否已經重複做過兩三次？
  2. 每次要提供的資料是否差不多？
  3. 輸出格式是否能說清楚？
  4. 哪些地方要停下來確認，是否已經很明確？
  5. 如果 Codex 做錯，能不能容易看出來並修正？

課堂先不要急著做什麼

  1. 不要一開始就要求全自動。
  2. 不要把正式發送、寫回系統、派薪或公開發布交給 Codex 自己決定。
  3. 不要把還沒穩定的做法包成長期工具。
  4. 先把情境、流程與確認責任說清楚，再討論是否需要 Skill 或 Agent。
