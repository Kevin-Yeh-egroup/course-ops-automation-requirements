練習 1

真實案例一：日週月報營運雷達

把日報、週報、月報會用到的 Gmail、Google Ads、好理家在後台與電子報訊號，整理成可檢查的營運摘要。

情境先看懂

這個案例一開始看起來只是「每天要看很多數字和信」。

真正困難的是來源很多，而且可信度不一樣。

Gmail 有真人回覆與系統通知，Google Ads 有投放數字，好理家在後台有實際使用狀態，電子報則是外部學習素材。

如果直接請 Codex 做結論，很容易把已確認、部分確認和還沒讀到的資料混在一起。

我要達到的目的

把每天、每週、每月要看的訊號分層，最後整理成可以交付、可以追問的報表。

如果不用 Codex，平常我會怎麼做
  1. 先打開 Gmail，看有沒有真人回覆、系統通知或重要回饋
  2. 再看 Google Ads 的花費、點擊與異常
  3. 打開好理家在後台，確認實際使用狀態
  4. 對照既有日報、週報、月報，補上缺漏或差異
  5. 整理成可回報的摘要，標出還沒確認的資料

我跟 Codex 互動的歷程

  1. 我先把問題說成「我需要一份今天可以信任的營運狀態」，而不是「幫我把所有數據整理好」。
  2. 接著把資料來源拆開：Gmail、Google Ads、好理家在後台、電子報，以及既有的日報、週報、月報。
  3. 第一版整理後，我再補充一個重點：報表要標清楚資料狀態，哪些已確認、哪些只有部分確認、哪些目前還讀不到。
  4. 後來流程逐漸固定：日報看今日狀態與異常，週報看趨勢與管理摘要，月報看累積成果與需要決策的地方。

我怎麼把需求說清楚

  1. 目的：確認今天、這週、這個月的營運狀態是否正常。
  2. 資料：Gmail、Google Ads、好理家在後台、電子報，以及既有報表。
  3. 風險：不要把未確認資料寫成結論，也不要漏掉 Ads 或後台異常。
  4. 先請 Codex 做的事：分來源整理、標出資料狀態、產出報表草稿，並列出需要人工重看的地方。

Codex 可以協助到哪裡

  1. 把 Gmail、Ads、後台與電子報分成不同訊號
  2. 整理今日異常、週趨勢與月累積重點
  3. 標出已確認、部分確認、目前讀不到的資料
  4. 把電子報整理成可審閱的觀察卡，而不是直接變成決策

仍然要由人確認

  1. Google Ads 數字是否真的來自當天後台
  2. 好理家在後台是否已成功開啟並確認
  3. Gmail 回饋是否需要真人回覆
  4. 週報或月報結論是否有足夠證據
  5. 哪些資料只能先標成待補
這題要學會的切分

學員要學到的是：報表不是把所有資料塞成一段結論，而是先說清楚來源、證據與限制。Codex 可以協助整理與寫草稿，但數字、異常、決策與對外說法仍要由人把關。

練習 2

真實案例二：逐字稿變成文章與通知草稿

把錄影或逐字稿整理成可審閱的文章素材，並留下處理狀態與待確認事項。

情境先看懂

這不是單純把逐字稿改成文章。

真實工作會先遇到幾個問題：錄影檔能不能處理、逐字稿是否完整、文章要放進哪個內容流程、哪一筆已完成、哪一筆還在等確認。

如果沒有把狀態整理清楚，後面很容易重複處理或漏掉素材。

我要達到的目的

把影片到文章的中間流程攤開，讓檔案狀態、文章草稿與待確認事項都能被追蹤。

如果不用 Codex，平常我會怎麼做
  1. 先確認錄影檔與逐字稿是否齊全
  2. 手動整理重點與可用段落
  3. 打開管理表確認這筆內容目前狀態
  4. 寫出文章草稿或摘要，再標出待確認句子
  5. 回到管理表更新進度，避免下次重複處理

我跟 Codex 互動的歷程

  1. 我先請 Codex 幫我盤點錄影與管理表，而不是直接叫它寫文章。
  2. 接著把流程拆成：找檔案、確認狀態、整理逐字稿、產文章草稿、回寫管理表。
  3. 中間發現排序、標題與狀態很重要；如果不整理清楚，後面就不知道哪一筆已完成。
  4. 最後我把可處理的錄影先批次處理，未確認的部分留在管理表，避免混在一起。

我怎麼把需求說清楚

  1. 讀者：文章最後要給一般民眾、學員，還是內部同仁看。
  2. 資料：錄影檔、逐字稿、管理表與文章位置在哪裡。
  3. 先做哪一步：先整理摘要、先做文章草稿，或先確認缺少哪些資料。
  4. 限制：不能自動發布、不能改變講者原意，也不能忽略待確認事實。

Codex 可以協助到哪裡

  1. 整理逐字稿重點
  2. 把口語內容改成文章草稿
  3. 列出需要人工查證的內容
  4. 協助回顧哪些素材已處理、哪些還沒完成

仍然要由人確認

  1. 講者原意是否保留
  2. 人名、日期與專有名詞是否正確
  3. 內容是否適合公開
  4. 文章是否真的可以放進正式流程
這題要學會的切分

學員要學到的是：內容工作不是貼上文字請 AI 改寫而已，要先說明讀者、用途、素材狀態與審稿邊界。

練習 3

真實案例三：自定義名詞與派薪前檢查

把候選名詞、修正對照與派薪前資料整理成審閱包，讓人可以清楚判斷下一步。

情境先看懂

這個案例很容易被誤會成讓 AI 判斷薪資。

實際上，我做的是比較保守的整理：先把候選名詞、修正對照、事件狀態與派薪前資料攤開，讓人看得到依據，再決定是否寫入正式系統。

我要達到的目的

讓承辦人看清楚哪些名詞可能可以納入、哪些已存在、哪些缺證據、哪些派薪前還不能動。

如果不用 Codex，平常我會怎麼做
  1. 先打開候選名詞與事件清單
  2. 對照既有名詞，確認是否已存在或疑似重複
  3. 查看事件狀態、工作類型與日期
  4. 手動整理可處理、待補證據、先暫停的項目
  5. 正式新增、關閉事件或派薪前，再請人複查

我跟 Codex 互動的歷程

  1. 我先讓 Codex 讀取目前仍在處理中的項目，整理成一份可審閱清單。
  2. 第一版不直接執行，而是先分成可納入、不可納入、已存在、需要補證據。
  3. 確認規則後，我才把可執行的批次獨立出來；正式新增、關閉事件與薪資建立都要另外確認。
  4. 做完後還要留下前後證據，知道哪一筆為什麼被處理、哪一筆為什麼暫停。

我怎麼把需求說清楚

  1. 影響範圍：名詞資料、事件狀態與派薪前確認。
  2. 判斷依據：候選名詞、修正對照、工作類型、日期與狀態。
  3. 不能代決定的事：正式新增、關閉事件、建立薪資。
  4. 先請 Codex 做的事：整理證據、分組、標記疑點、列出待確認項目。

Codex 可以協助到哪裡

  1. 把大量候選資料整理成清楚分類
  2. 找出已存在或疑似重複項目
  3. 標出缺證據與低信心資料
  4. 產出承辦人可以審閱的確認包

仍然要由人確認

  1. 是否真的可以新增正式名詞
  2. 是否符合派薪資格
  3. 是否可以關閉事件
  4. 是否要建立薪資或暫停處理
這題要學會的切分

學員要學到的是：牽涉正式紀錄或薪資時，Codex 先做整理與提示，不直接替人下結論。

練習 4

真實案例四：課程改版包與交接清單

把模糊的改版想法整理成教材改版包，讓投影片、練習題與上課流程一致。

情境先看懂

這個案例就是這份教材本身。

原本的課程有課務、逐字稿、表格與活動行政，但你覺得還是不夠像真實工作。

後來我們改用你在 Codex 裡實際做過的工作，去識別化後包裝成學生能理解的情境。

我要達到的目的

讓學員看到教材如何從模糊感受變成可上課材料：先說哪裡不真實，再找真實案例，最後改投影片、練習頁與檢查方式。

如果不用 Codex，平常我會怎麼做
  1. 先看原本教材哪裡不夠貼近真實工作
  2. 回想最近實際做過哪些 Codex 工作
  3. 挑出可以去識別化、也適合上課的案例
  4. 手動改投影片、練習頁與課綱文字
  5. 最後逐頁檢查案例是否一致、語氣是否適合學員

我跟 Codex 互動的歷程

  1. 你先說：課程與練習題太不實際，希望學生看到可以做到什麼、怎麼做、怎麼確認。
  2. 我先從你的工作記錄中找可去識別化的案例，再和原本四個情境對照。
  3. 你再指定案例三改成自定義名詞與派薪前檢查、案例四改成課程改版。
  4. 後續我們又調整呈現方式：先講情境與歷程，再講工作切分，避免一開始就堆很多專有名詞。

我怎麼把需求說清楚

  1. 問題：學生會覺得題目不真實、太像練習題。
  2. 方向：改用真實工作去識別化，包裝成可上課的情境。
  3. 範圍：案例、投影片、練習頁、課程說明與檢查方式。
  4. 限制：不要露出敏感資料，也不要讓學員以為可以全自動。

Codex 可以協助到哪裡

  1. 整理你提出的口語需求
  2. 把案例對照到原本課程架構
  3. 改寫成學員能懂的情境
  4. 同步更新多個教材頁面並檢查連結

仍然要由人確認

  1. 案例是否真的代表你的工作
  2. 語氣是否適合學員
  3. 是否過度技術化
  4. 是否有不該公開的內部資訊
這題要學會的切分

學員要學到的是：和 Codex 合作時，可以先說感受與目標，再一輪一輪把教材、流程或文件修到可用。
