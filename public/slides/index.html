使用心智模型

和會執行工作的秘書開會

開會方式

操作流程

一題照這七步走

1. 說明情境

現在遇到什麼行政工作？

2. 提供資料

貼上安全範例、副本或低風險素材。

3. 指定輸出

表格、清單、草稿、流程或 checklist。

4. 標出確認點

哪些地方要補問、要人看、要保留判斷。

5. 先拆工作

請 Codex 先整理步驟，再產出草稿。

6. 人工檢查

看有沒有誤解、漏項或語氣不合。

7. 要求修正版

把修正意見變成下一版輸出。

安全使用方式

學會把成果變得可確認

會練會

整理、摘要、檢查缺漏，產出可修正的草稿。

會標出

哪些內容要人工確認、由誰確認、何時才能使用。

會帶走

一份可重複指令、一份工作檢查表與後續改善清單。

安全不是把事情停住，而是讓下一步更清楚、更好交接。

四個可選題目

四題都照同一個節奏操作

學員不用四題全做。共同示範後，每個人選最接近自己工作的一題，照下面三步跑一次。

1. 選題與貼資料

選一段低風險、明天就可能用到的工作，貼上範例或副本。

2. 用短版指令產出

說清楚要整理、檢查或產草稿，要求 Codex 列出人工確認點。

3. 人工檢查後修正

檢查日期、金額、人名、外部發送與正式資料更新，再要求修正版。

可選題目

課程提醒、逐字稿內容、表格檢查、活動行政包。

課後留下

一段可重複指令、一份 Codex 產出、一份人工確認清單。

題目一

課程提醒與每日工作台

把課程資料整理成今天可以處理的待辦與提醒草稿。

學員怎麼做
  1. 貼上一筆課程或活動資料。
  2. 補上日期、地點、對象、負責人與目前狀態。
  3. 請 Codex 分成今日到期、已逾期、等待回覆、需確認。
  4. 檢查日期與對象，再把提醒草稿改成自己的語氣。
請把以下課程資料整理成今日課務工作台。 請輸出：今日到期、已逾期、等待回覆、需要人工確認、可修改提醒草稿。 如果資料不足，請列出補問問題，不要自己猜。 資料：
先準備

課程資料、日期時間地點、負責人、等待回覆事項。

會產出

工作台、提醒清單、等待回覆追蹤、提醒草稿。

要檢查

日期、對象、提醒文字、外部發送與正式資料更新。

到練習 1 操作頁 完成後填成果檢查

題目二

逐字稿與內容草稿

把逐字稿先整理成摘要與可修改草稿，再由人確認事實與語氣。

學員怎麼做
  1. 貼上一段逐字稿、會議紀錄或音檔摘要。
  2. 說明讀者是同仁、學員、合作單位或社群。
  3. 請 Codex 先抓重點與待確認事實，再產草稿。
  4. 人工確認人名、日期、專有名詞與可發布程度。
請將以下逐字稿整理成內容草稿。 請輸出：一段摘要、三個重點、文章草稿、社群短文、需要人工確認的事實清單。 請使用台灣職場常用的繁體中文語氣。 資料：
先準備

逐字稿或摘要、活動名稱、讀者、輸出格式。

會產出

摘要、文章草稿、社群短文、待確認清單。

要檢查

事實、語氣、可公開程度、是否忠於原意。

到練習 2 操作頁 完成後填成果檢查

題目三

表格狀態與核銷檢查

先做只讀檢查，把缺漏、衝突、低信心資料列出來，不直接下正式結論。

學員怎麼做
  1. 貼上表格片段或上傳表格副本。
  2. 說明哪些欄位必填、哪些規則要檢查。
  3. 請 Codex 找缺漏、重複、格式錯與狀態衝突。
  4. 保留來源列，逐項確認哪些要補問或修正。
請只讀檢查以下表格資料。 請列出：缺漏欄位、格式異常、重複資料、狀態衝突、需要人工確認的金額或日期。 若資料不足，請列出補問問題，不要做正式核銷或付款結論。 資料：
先準備

表格副本、必要欄位、日期/狀態/金額規則。

會產出

異常清單、補問清單、人工確認清單。

要檢查

來源列、異常原因、金額只做試算。

到練習 3 操作頁 完成後填成果檢查

題目四

活動行政包

把活動拆成課前、課中、課後，產生可交接的流程與清單。

學員怎麼做
  1. 貼上活動日期、地點、對象、人數與人力資訊。
  2. 列出物資、場地、餐食、通知與既有範本。
  3. 請 Codex 拆成課前、課中、課後，產出分工與 checklist。
  4. 人工確認外部通知、個資揭露、場地餐食與課後建檔。
請把以下活動資料整理成活動行政包。 請輸出：課前/課中/課後流程、分工表、通知草稿、物資清單、風險清單、可交接 checklist。 請把需要人工確認的項目另外列出。 資料：
先準備

活動資訊、人力、物資、場地與既有範本。

會產出

流程、分工、通知草稿、物資與風險清單。

要檢查

場地餐食、名單、外部通知、個資與建檔事項。

到練習 4 操作頁 完成後填成果檢查

檢查輸出

看輸出時問三件事

有沒有幫我省整理時間？

資料是否更清楚、待辦是否更集中？

有沒有漏掉重要判斷？

需要人確認的地方是否有列出來？

下次能不能重跑？

指令、資料格式與檢查方式是否足夠清楚？

效果記錄

用簡單表格留下證據

原本花多久？

估計原本整理、查缺漏、寫草稿需要多少時間。

Codex 幫到哪裡？

記錄省下的整理時間與仍需人工確認的部分。

下一步怎麼改？

改指令、補資料、整理成方法小抄，或暫時維持人工。

升級語言

指令、方法小抄、助理角色卡怎麼分

指令

一次請 Codex 幫你做一版。

方法小抄

同一類工作跑過幾次後，把穩定做法寫下來。

助理角色卡

把任務、邊界、資料來源、檢查方式寫清楚。

這堂課先學會分辨與寫草稿，讓之後的工具化更穩。

協作方式

不用背流程，要學會怎麼跟 Codex 開會

學員之後會在自己的電腦和 Codex 協作。畫面、帳號與授權狀態可能不同，所以重點不是記住所有按鈕，而是會問、會確認、會請 Codex 驗證。

1先說目標

我要做什麼、給誰看、哪些資料可以公開。

2請它拆步驟

先說明要做哪些事，不急著執行。

3確認邊界

會改檔案、連外部服務或需要登入時，先停下來。

4一次一小步

看完結果再往下一步，不用一口氣全做完。

5請它驗證

回報網址、畫面、連結、noindex 與人工確認點。

我不用背完整流程，請你像專案秘書一樣帶我做。 請先幫我拆成 3 到 5 個步驟，並標出哪些你可以做、哪些需要我登入或授權、哪些會公開到網路上。 請先說明，不要直接執行。

課程尾聲延伸

如果成果要公開呈現，走這條路線

把 Codex 做出的頁面或小工具，整理成 GitHub repo（放專案檔案和修改紀錄的雲端資料夾），再部署到 Vercel production（正式可開啟的公開網址）。這段是課後探索，不是前面 90 分鐘的必做題。

1Codex 做頁面

先做本機版本，也就是目前電腦或 Codex 工作區看得到，還不是公開網址。

2GitHub repo

建立版本庫，留下 README。README 就像交接說明，寫給之後維護或審查的人看。

3部署到 Vercel

連到 repo，產生正式網址。

4跨裝置檢查

手機、桌機、連結、導覽與 noindex（請搜尋引擎不要收錄的設定）。

5確認後分享

確定沒有個資、內部資料或正式敏感內容。

帳號與外掛

開始公開部署前，先準備三件事

GitHub 帳號

用來放專案與版本紀錄。註冊後要完成 Email 驗證，才能順利建立 repo。

Vercel 帳號

用來把 GitHub repo 部署成公開網址。建議用 GitHub 登入，匯入 repo 會比較直覺。

Codex 外掛

外掛是讓 Codex 可以連到 GitHub、Vercel 或瀏覽器檢查的授權能力，不是讓 Codex 自己開公司帳號。

可以這樣問 Codex
  1. 目前我需要哪些外掛？
  2. 每個外掛會用來做什麼？
  3. 需要我登入或授權哪個帳號？
  4. 完成後你會怎麼驗證？
請檢查目前可用的 Codex 外掛。 這個任務需要 GitHub、Vercel 和 Browser 相關能力。 如果外掛尚未啟用，請先告訴我用途、需要的授權，以及啟用後的驗證方式。 請不要自行建立外部帳號、不要付款、不要發布未經確認的內容。
看帳號與外掛步驟 看授權怎麼選 回公開部署總覽

確認判斷

看到任何確認畫面，不急著按同意

不只 GitHub / Vercel。只要會改檔案、登入授權、公開發布、外部寄送、刪除、安裝、付款或碰到密碼金鑰，都先停下來問 Codex：會改哪裡、會送去哪裡、能不能復原。

只讀或本機草稿

通常可以先做，例如整理、檢查、產生本機草稿或開本機預覽。

改檔案、commit、push、deploy

先請 Codex 列出會改什麼、送去哪裡，等本人確認後再做。

外部寄送、刪除、安裝、公開

先停下來確認收件人、檔案、公開範圍、是否能復原。

付款、密碼、金鑰、公司權限

課堂不要直接按。截圖或記下問題，找主管或帳號管理者確認。

如果畫面跳出授權或確認，請先幫我判斷： 這會改哪裡？會把資料送去哪裡？能不能復原？會不會碰到個資、正式資料、金額、密碼或公司權限？ 如果安全，請告訴我應該選哪一個；如果不安全，請叫我停下來。
看完整授權選擇表 看操作指令

具體操作

請 Codex 協助把成果整理到可檢查的公開網址

把它想成一位會幫你執行工作的專案秘書：先確認目標，再做本機版本，接著整理 repo、部署、驗證；需要登入、授權或公開發布時，先停下來給你確認。

建頁面

「請先做本機版本，不要放個資，完成後用瀏覽器檢查手機和桌機畫面。」

建 repo

「請先列出會提交的檔案，等我確認沒有敏感資料，再建立 GitHub repo。」

部署成正式網址

「請部署到 Vercel production，回報網址、部署紀錄與 noindex 狀態。」

公開前驗收

「請檢查跨裝置、連結、文字、台灣用語，以及不該公開的資料。」

公開頁可以被轉傳與截圖；review 階段的 noindex 不是隱私保護。
