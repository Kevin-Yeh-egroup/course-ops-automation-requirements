# 共用模組：狀態檢查與對帳規則

## 目的

佩欣、思宜、怡君、瑜君、阿丸、素菁的共同問題不是單一欄位缺漏，而是「不同系統顯示的狀態不一致」。這份規則用來定義第一版可檢查的狀態。

## 共用檢查類型

| 檢查 | 判斷 | 輸出 |
| --- | --- | --- |
| 必填缺漏 | 必要欄位空白或格式不符 | 缺漏清單 |
| 狀態衝突 | A 系統顯示完成，B 表格未更新 | 對帳異常 |
| 逾期未完成 | 超過截止日仍未完成 | 逾期清單 |
| 疑似重複 | 同人、同日期、同金額或同案件重複 | 疑似重複清單 |
| 高風險寫回 | 會影響薪資、個資、外部通知或系統狀態 | 只產生待人工確認 |

## 角色化應用

| 角色 | 第一版重點 |
| --- | --- |
| 佩欣 | 課務申請、核銷、庫存、季刊、分區會議、諮詢紀錄的每日工作台 |
| 思宜 | InfoCenter、LINE、Google Sheet、引導員電訪與信扶匯入模板的狀態對帳 |
| 怡君 | 分享會/Podcast 素材到位、逐字稿/文章/社群草稿、寄送對象、交接狀態與交通核銷試算 |
| 瑜君 | 南區課務的課前提醒、缺漏檢查、派課摘要與發票/交通行政追蹤 |
| 阿丸 | 候補名單、系統工作區、正式場次、活動行政包與 InfoCenter 建檔草稿 |
| 素菁 | 月結試算、個人確認包、Ivy 輸出預覽、匯款前檢查與發票風險提示 |

## 審核邊界

第一版只做讀取與草稿。以下項目不得自動完成：

- 外部訊息發送
- Line 群組發文
- 部落格、粉專、Podcast 或 Email 對外發布
- InfoCenter 寫入
- MIS 報名搬移、取消報名或寄送活動通知
- 影響薪資或核銷的完成勾選
- 月結薪資、匯款資料或發票資料的正式輸出
- 個案資料與敏感資訊的自動改寫
- 未經確認的 Calendar 邀請
