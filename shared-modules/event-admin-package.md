# 共用模組：活動行政包與候補比對

## 目的

這個模組用來整理活動行政流程中最容易重複、漏改或手動耗時的部分：候補名單比對、系統工作區搬移建議、活動前文件包、行前通知草稿、活動後 InfoCenter 建檔草稿。

目前主要參考阿丸的需求。後續若其他同仁也有活動、課程、工作坊或說明會的行政包需求，可以合併到這個模組。

## 核心輸入

| 類型 | 例子 | 注意事項 |
| --- | --- | --- |
| 場次資料 | 日期、地點、容量、活動流程、工作人員 | 必須能對到正式場次 |
| 候補資料 | Google 候補表、Email 候補詢問 | 不自動寄信，只產生草稿 |
| 報名資料 | MIS 匯出、系統工作區報名者、正式場次名單 | 需比對同人、多場次、已上課紀錄 |
| 文件範本 | 工作流程表、簽到表、學員名單、分組座位表 | 第一版產生草稿，不直接視為正式版 |
| 活動後資料 | 照片、簽到表、活動摘要、附件 | 產生 InfoCenter 草稿與上傳清單 |

## 第一版產出

| 產出 | 用途 |
| --- | --- |
| 候補摘要 | 每日候補/一般問題/不確定分類 |
| 候補比對報表 | 可通知、已上過課、已完成報名、待人工確認 |
| 系統工作區搬移建議 | 誰應移到哪個正式場次，哪些暫存報名需取消 |
| 活動行政包 | 工作流程表、簽到表、學員名單、分組座位表 |
| 行前通知草稿 | 場次通知內容、收件名單、寄送前檢查 |
| InfoCenter 建檔包 | 活動摘要、欄位草稿、附件清單 |

## no-op 規則

遇到以下情況時，只產生待確認清單，不產生正式文件或外部動作：

- 場次日期、地點或正式場次 ID 缺漏。
- 學員姓名、Email、電話缺漏或疑似同名。
- 同一人出現在多個候補場次或多個分組。
- 系統工作區報名者無法對回原候補場次。
- 分組規則、便當/物資規則或人力資料不足。
- 阿丸尚未確認寄信、搬移、取消報名、上傳或寫入。

## 治理邊界

- 公開頁只放流程摘要，不放真實學員姓名、手機、單位、報名狀態或原始逐字稿。
- 自動寄信、修改 MIS、修改 Google 表單/Sheet、上傳附件、寫入 InfoCenter 都必須留在人工核准之後。
- 文件生成可以先 local-only；正式公開展示需使用假資料或去識別化資料。
