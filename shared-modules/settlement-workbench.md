# 共用模組：月結對帳與結算工作台

## 目的

這個模組用來銜接課務與行政資料的最後一段：當課程、諮詢、企劃、交通與補扣款資料逐步整理完，系統需要把它們轉成可追溯、可確認、可輸出的月結資料。

目前主要參考素菁的帳務/月結需求，並納入怡君提到的交通公里數與不同單位費率核銷需求。後續若雨虹、奕吟、思璇或其他同仁也有報帳、核銷、薪資、發票相關流程，可以再合併進來。

## 核心輸入

| 類型 | 例子 | 注意事項 |
| --- | --- | --- |
| 工作紀錄 | 課程、訪視、諮詢、講師、企劃、稿件 | 必須保留日期、人員、工作類型、來源 |
| 規則資料 | 角色、專案、單價、級距、例外條件 | 不宜公開完整薪資規則 |
| 歷史狀態 | 累積趟數、目前級距、個人例外 | 需要跨月保留，不可只看本月 |
| 調整項 | 退款、補稅、差旅、設備扣款 | 一律列入高風險人工審核 |
| 交通核銷 | 起點、終點、公里數、單位費率、單據 | 路線與費率只做試算，正式核銷前人工確認 |
| 輸出格式 | Ivy 報帳表、個人確認包、匯款前檢查 | 先做預覽，不自動送出 |

## 第一版產出

| 產出 | 用途 |
| --- | --- |
| 月結 Dashboard | 看本月匯入、試算、異常、確認、輸出進度 |
| 異常清單 | 找不到人、找不到規則、疑似重複、金額跳動 |
| 個人確認包 | 給夥伴確認本月明細與總額 |
| Ivy 輸出預覽 | 把確認後資料整理成 Ivy 需要的分類格式 |
| 匯款前檢查 | 檢查總額、分類加總、帳戶缺漏與補扣款狀態 |

## no-op 規則

遇到以下情況時，只產生待確認清單，不進入正式輸出：

- 找不到人員或同名無法判斷。
- 工作類型沒有對應規則。
- 單價與歷史紀錄不一致。
- 金額為負數或異常跳動。
- 帳戶、身分、發票或付款資料不完整。
- 本人尚未確認，或素菁尚未審核。

## 治理邊界

- 公開頁只放流程摘要，不放完整薪資規則、帳戶、身分證、地址、電話或完整逐字稿。
- Vercel production review 即使有 noindex，仍然是 link-accessible，不可當成隱私控管。
- 自動匯款、正式開票、外部訊息發送、薪資主檔改寫都必須留在人工核准之後。
