# 工作流蒐集與 AI 評估模板

## 目的

這份模板用來陪伴夥伴把真實工作講清楚。重點不是一開始就問「要不要自動化」，而是先整理工作怎麼開始、資料從哪裡來、現在怎麼處理、哪裡需要人判斷，以及什麼樣的 AI 協助才不會增加風險。

## 使用時機

| 情境 | 適合怎麼用 |
| --- | --- |
| 新夥伴第一次整理工作 | 先挑一項最常做、最容易漏或最耗時間的工作，不一次問完全部職務 |
| 已整理過的夥伴要補細節 | 回到單一工作流，補觸發條件、資料來源、例外、確認人與輸出物 |
| 準備做 AI 沙盒實驗 | 先確認資料是否可去識別化、是否只能只讀、是否需要人工核准 |
| 準備給主管或團隊看 | 只呈現流程、痛點、預期效益與風險邊界，不放原始個資或完整逐字稿 |

## 訪談前先確認

| 確認項目 | 建議問法 |
| --- | --- |
| 這次只談哪一項工作 | 今天先挑一件你最常做、最怕漏或最希望有人幫忙整理的工作，可以嗎？ |
| 資料能不能拿出來 | 你可以提供去識別化範例、欄位名稱、假資料或截圖描述嗎？ |
| 哪些資訊不能進公開頁 | 有沒有姓名、電話、帳戶、身分證、薪資、個案狀態、發票或內部連結？ |
| 這件事的完成定義 | 你做到哪一步會覺得這件事算完成？誰還需要確認？ |
| 目前能接受的協助方式 | 你比較希望 AI 幫你整理清單、找缺漏、產草稿，還是只做提醒？ |

## 工作流蒐集卡

| 欄位 | 要填什麼 | 範例提示 |
| --- | --- | --- |
| 工作名稱 | 用夥伴聽得懂的名稱，不用系統名稱 | 課前提醒、候補名單比對、月結確認包 |
| 主要負責人 | 誰每天或每週實際處理 | 佩欣、思宜、瑜君、阿丸、素菁等 |
| 觸發條件 | 什麼事情發生後，這項工作就要開始 | 新表單、新課程、月底、活動前一週、有人回覆 |
| 資料來源 | 原始資料在哪裡 | Google Sheet、表單、InfoCenter、MIS、Email、LINE、Excel、Word 範本 |
| 現在步驟 | 夥伴現在實際怎麼做 | 先下載、再篩選、貼到群組、人工確認、回填狀態 |
| 主要產出 | 最後要交出什麼 | 提醒清單、課務摘要、匯入模板、文件包、對帳草稿 |
| 頻率與時間點 | 多久做一次、何時最急 | 每日、每週、月底、課前 2 週、活動後 3 天 |
| 常見痛點 | 最容易花時間、出錯或漏掉的地方 | 欄位缺漏、狀態不同步、重複貼上、金額規則複雜 |
| 例外情況 | 哪些情況不能照一般規則跑 | 日期未定、講師未派、個案敏感、金額不合理、同名無法判斷 |
| 人工確認點 | 哪些地方一定要人看過 | 對外發送、正式寫回、匯款、發票、資格判斷、個案處置 |
| 可接受的 AI 協助 | 夥伴願意先試哪一種 | 摘要、缺漏檢查、提醒、比對、草稿、試算、文件產生 |
| 不適合 AI 的部分 | 暫時不交給 AI 判斷或執行 | 自動取消、自動核准、自動匯款、自動寄出、自動改正式資料 |

## 陪伴式訪談問題

1. 你今天如果沒有做這件事，最可能會造成什麼問題？
2. 這件事現在最花時間的是「找資料」、「判斷狀態」、「寫訊息」、「整理格式」，還是「等別人回覆」？
3. 你通常會看哪幾個地方才敢判斷下一步？
4. 哪些欄位缺了，你就不能繼續做？
5. 哪些情況你一定會停下來問主管、會計、規劃師、講師或同事？
6. 如果 AI 只幫你產一張清單或草稿，哪一種最有幫助？
7. 你最不希望 AI 自動做什麼？
8. 這件工作如果先用假資料測試，怎麼判斷它真的有幫到你？

## AI 協助成熟度

| 等級 | 說明 | 適合例子 | 邊界 |
| --- | --- | --- | --- |
| L0 先不使用 AI | 流程尚不清楚，或資料太敏感 | 個案資格判斷、正式薪資結論 | 先只整理工作流，不做工具 |
| L1 整理與摘要 | 把散落資料整理成可讀摘要 | 逐字稿摘要、活動紀錄、課務需求摘要 | 必須保留來源與待確認事項 |
| L2 缺漏與提醒 | 找出缺欄、到期、逾期、等待回覆 | 課前提醒、LINE 未驗證、欄位缺漏 | 不自動催人或寫回正式系統 |
| L3 草稿與文件 | 產生可修改的文字或文件 | Line/Email 草稿、活動行政包、月結確認包 | 人工確認後才使用或送出 |
| L4 受控半自動 | 在規則穩定後，輔助低風險寫回 | Calendar 草稿、狀態欄更新建議、檔案命名 | 每次送出前要有預覽、核准與紀錄 |

## AI 沙盒前檢查

| 檢查 | 通過條件 |
| --- | --- |
| 資料安全 | 使用假資料、去識別化資料，或只保留欄位名稱與描述 |
| 原始資料 | AI 輸出不能取代原始表單、Sheet、InfoCenter 或正式紀錄 |
| 人工確認 | 對外訊息、寫回、金額、個案、薪資、發票都有人審點 |
| no-op 規則 | 資料不足、日期未定、低信心比對時，只產生待補清單 |
| 成效判斷 | 先定義這次要驗證省時間、少漏件、少重複，或更容易交接 |

## 可交給不同觀點檢視的問題

| 觀點 | 主要看什麼 |
| --- | --- |
| 流程拆解 | 觸發、輸入、步驟、產出與例外是否清楚 |
| 資料欄位 | 來源欄位、必填欄位、狀態欄、日期欄、敏感欄位是否可判讀 |
| 風險控管 | 哪些地方會影響個資、金額、外部承諾或正式系統 |
| AI 可行性 | 哪些適合摘要、比對、提醒、草稿，哪些不適合自動化 |
| 夥伴接受度 | 這個協助方式是否真的減少負擔，還是增加檢查成本 |

## Agent 討論前置卡

若需要用多個 agent 或不同觀點協助討論，先填這張卡，再啟動討論。

| 欄位 | 填寫內容 |
| --- | --- |
| 討論目的 | 這次要判斷哪一項工作是否適合 AI 協助 |
| 必須做出的決定 | 採用、先驗證、暫停，或需要再訪談 |
| 停止條件 | 已能列出下一個最小實驗，或確認資料不足 |
| 輸出格式 | 強訊號、有用的分歧、現在採用、下一步驗證、暫停項目、證據產物 |
| 需要的證據 | 工作卡、欄位樣本、去識別化資料、夥伴回饋、現有範本 |
| 不在範圍 | 不做外部發送、不寫回正式系統、不做薪資或個案結論 |
| 核准門檻 | 涉及帳號、正式資料、外部系統、排程或發送前需人工核准 |

## 建議的第一批證據產物

| 產物 | 用途 |
| --- | --- |
| 一頁式工作流卡 | 讓夥伴確認「這是不是你真正在做的事」 |
| 欄位地圖 | 確認資料來源、必填、日期、狀態與敏感欄位 |
| 只讀檢查報告 | 用假資料或去識別資料產生缺漏、逾期、衝突清單 |
| 草稿包 | 產生提醒、補問、派課摘要、活動通知或月結確認草稿 |
| 回饋紀錄 | 請夥伴標記有幫助、太吵、判斷錯誤、需要補資料的地方 |

## 下一步建議

| 順序 | 工作 |
| --- | --- |
| 1 | 先用這份模板補雨虹、奕吟、思璇三位待補資料 |
| 2 | 從既有六位夥伴中，各挑一項最清楚的工作流回訪補細節 |
| 3 | 用去識別化資料建立一份只讀提醒/缺漏/草稿範例 |
| 4 | 請夥伴回饋範例是否真的減少工作負擔 |
| 5 | 再決定是否進入 Google Sheet、Apps Script、Codex 本機工具或內部工作台 |
