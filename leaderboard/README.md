# 課後作業評分與排行榜

狀態：2026-07-06 已完成評分，並已依 Kevin 確認公開學員層級成績單到 `public/leaderboard/`。正式評分以 `rubric/rubric-v2.yaml` 為準。

本資料夾用來整理「Codex 行政工作實驗課」課後作業的評分標準、評審紀錄與排行榜。參加課堂的人多數是 Codex 新手，所以評分重點不是進階技巧、漂亮介面或複雜自動化，而是看學員是否能把自己工作上的一小段真實行政流程，整理成可用、可檢查、可交接的成果，並且把人工確認與安全邊界講清楚。

## 評分依據

| 指標 | 配分 | 核心問題 |
| --- | ---: | --- |
| Codex 與工作實際結合 | 35 | 是否選到自己工作中的真實片段，並說清楚 Codex 放在哪一步、成果如何回到工作流程。 |
| 與 AI 的互動能力 | 30 | 是否能提供背景、資料、限制、輸出格式與人工確認規則，並展現修正 AI 產出的能力。 |
| 需求轉換成現實成果的能力 | 35 | 是否能把模糊需求變成可使用、可檢查、可交接的草稿、表格、流程、頁面、清單或工具。 |

安全邊界作為門檻，不作為主要競分項；紅線作品不列入排行榜。

## 不作為主要加分

- 使用很多 Codex 指令、agent、prompt 技巧，但工作成果不清楚。
- 做出漂亮 UI 或公開頁，但沒有工作情境、檢查證據或人工確認。
- 追求全自動，卻沒有停在草稿、dry-run 或人工確認。
- 技術很複雜，但下一位同仁無法接手。

## 評審團角色

| 角色 | 負責看什麼 |
| --- | --- |
| 課程對齊評審 | 是否符合課程目標：看懂 Codex 如何結合工作，而不是展示技巧。 |
| 風險與人工確認評審 | 是否有個資、金額、正式資料、外部發送、帳號權限或公開部署風險。 |
| 工作實用性評審 | 成果是否真的能放回工作流程，減少漏項、節省整理時間、支援交接。 |
| AI 互動評審 | 是否能把需求、限制、判斷規則與修正回合講清楚。 |
| 證據與資料品質評審 | 是否有來源、檢查紀錄、截圖、README、操作紀錄或修正紀錄。 |
| 台灣職場讀者評審 | 文字、說明與交接方式是否適合台灣同仁或合作單位閱讀。 |

## 評分流程

1. 把學員原始檔放到 `submissions/raw/<submission_id>/`。
2. 在 `submissions/submissions.csv` 登記一列收件資料。
3. 先建立 `submissions/evidence/<submission_id>.md`，摘要作品、來源、輸出、風險與可檢查證據。
4. 每位評審在 `scores/scorecards/<submission_id>/` 建立自己的 scorecard。
5. 彙整到 `scores/score-summary.csv`。
6. 安全狀態通過後，才更新 `leaderboard/leaderboard.csv` 與 `leaderboard/leaderboard.md`。
7. 同分或例外裁示寫到 `review-notes/tie-decisions.md`，不要直接改原始分數。

## 安全閘門

- 紅線作品不列入排行榜：未授權外部寄送、正式資料異動、刪除、付款、帳號權限變更、公開個資或敏感資料、把 AI 推測包裝成已驗證事實。
- 有公開頁或部署網址時，必須檢查資料已去識別、手機與桌機可開啟，內部 review 階段至少要確認 noindex 或 robots 邊界。
- 沒有人工確認欄位，最高 80 分；沒有檢查證據，最高 70 分；資料邊界不清，最高 75 分。
